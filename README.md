# 시몬ONE 행사캘린더

클라우드 전환 구성은 [worker/README.md](worker/README.md)를 참고하세요. GitHub Pages가 화면을 제공하고, Cloudflare Worker가 API·로그인·텔레그램 연결을 처리하며, Google Sheets와 Drive에 업무 데이터와 첨부파일을 저장합니다. 기존 Node.js + SQLite 실행 방법은 아래 로컬 개발용으로 유지합니다.

기존 HTML 목업의 디자인을 바탕으로 만든 Node.js + SQLite 웹 시스템입니다. Node.js 24 이상이 필요합니다.

## 실행

1. 프로젝트 폴더에서 `npm install`을 실행합니다.
2. `.env.example`을 `.env`로 복사하고 초기 관리자·부서 비밀번호를 8자 이상으로 설정합니다.
3. `npm start`를 실행하고 `http://localhost:3000`에 접속합니다.

계정은 `admin`(기획부 관리자)과 `department-01`부터 `department-23`까지의 23개 부서 계정입니다. 비밀번호를 설정하지 않은 첫 실행에서는 각 계정의 무작위 초기 비밀번호가 터미널에 출력됩니다. 초기 비밀번호는 DB가 만들어질 때만 반영되며, 이후에는 웹에서 자기 비밀번호를 변경합니다. 변경 후에는 다시 로그인합니다.

## 기능과 확정 규칙

- 월 이동, 오늘 이동, 부서·상태 필터, 여러 날 및 종일 행사 표시
- 시작·종료 시간은 30분 단위 선택; 예상 인원 필수, 실제 참여 인원은 관리자 선택 입력
- 부장단·관리자 웹 등록, 텔레그램 봇 등록·수정·삭제; 등록 즉시 캘린더 표시
- 승인·반려·취소 절차 없이 등록·수정·삭제 이력만 보존
- 총회·지파·교육·정기·기타 행사 유형과 유형별 색상, 관리자의 유형명·색상 관리
- 행사 종료 후 등록자는 실제 참여 인원과 아카이브만 수정하고, 관리자만 행사 기본정보를 수정
- 삭제는 `삭제됨` 상태로 처리하며 삭제자·삭제 시각·변경 이력 보존
- 부서 추가·이름 변경·비활성화, 기존 행사·아카이브 보존
- 부서별 행사·협력 행사 열람, 전체 아카이브 열람 및 통합 검색
- 등록 행사 수·완료 행사 수·아카이브 게시글 수 통계
- 캘린더 PNG 이미지 다운로드 및 모바일 웹/PWA 설치
- 행사마다 여러 게시글; 게시글마다 사진 최대 10장/합계 500MB, 동영상 1개/500MB; 게시글과 첨부 수정·삭제
- 캘린더 날짜 칸 클릭 시 해당 날짜의 종일 행사 등록 모달, 행사 상세에서 해당 행사 아카이브 작성으로 이동
- 별도 아카이브 모아보기 페이지에서 작성 날짜 최신순으로 게시글·사진·동영상 표시, 스크롤 시 다음 10개씩 자동 조회
- 아카이브 및 파일은 로그인 사용자 전체 열람 가능; 남은 디스크 용량 표시

## 텔레그램 연동

BotFather에서 만든 봇 토큰을 `TELEGRAM_BOT_TOKEN`에 설정하고, 봇을 접수 알림방에 추가합니다. 메시지를 보낼 수 있는 권한을 부여한 뒤 방의 chat ID를 `TELEGRAM_NOTICE_CHAT_ID`에 입력합니다. `PUBLIC_URL`에는 운영 HTTPS 주소를 입력합니다.

봇 개인 대화에서 `/start` 또는 `/menu`를 입력하면 등록·수정·삭제 웹 화면 링크가 나옵니다. 텔레그램 내부 브라우저 또는 일반 브라우저에서 열 수 있습니다. 링크는 1시간 동안 유효한 임시 접수 권한을 부여합니다. 봇 사용자는 부서를 선택해 행사를 등록하고, 선택한 행사를 수정·삭제할 수 있습니다. 봇 링크에서는 승인·반려 및 아카이브 접근이 불가능합니다.

롱 폴링 방식으로 외부 webhook 포트는 필요 없습니다. 같은 봇으로 다른 폴링 프로그램을 함께 실행하지 마세요. 기존 webhook이 설정된 봇은 해제해야 합니다. 연동 정보가 없으면 웹 기능은 정상 동작하고 알림은 DB에 전송 대기로 쌓입니다. 전송 실패는 자동 재시도되며, 재시작이나 통신 장애 시 중복 알림이 발생할 수 있습니다.

## 운영 및 배포

준비한 도메인의 HTTPS 역방향 프록시를 이 서버의 3000 포트로 연결합니다. 프록시에서 `Host`, `X-Forwarded-Proto`를 전달하고 서버 포트는 프록시에서만 접근하도록 설정합니다. 게시글당 첨부 합계가 최대 1GB이므로 프록시의 요청 크기 제한과 업로드 시간 제한을 충분히 설정합니다. 예: Nginx `client_max_body_size 1100m; proxy_read_timeout 600s;`.

운영 PC 재부팅 후 `npm start`가 자동 실행되도록 작업 스케줄러 등에 등록하고 작업 디렉터리를 프로젝트 폴더로 지정합니다. 외부 배포에서는 `.env`, `data`를 정적 웹 디렉터리에 두지 않습니다. 개발용 `public` 폴더만 정적 제공됩니다.

행사 DB는 `data/calendar.sqlite`, 첨부는 `data/uploads`에 저장됩니다. 영구 보관을 위해 운영 PC와 별도 디스크에 매일 백업하세요. **서버를 중지한 상태에서 `data` 폴더 전체를 복사**하면 DB와 첨부를 함께 일관되게 보관할 수 있습니다. `.env`도 별도로 보관합니다. 복원은 서버를 중지하고 백업의 `data`를 되돌린 뒤 실행합니다. 실제 백업 대상 디스크와 자동 작업 등록은 운영 환경에서 설정해야 합니다.

## 검증

`npm test`는 HTTP 서버를 실행해 행사 유형, 등록 즉시 표시, 승인·반려·취소 API 제거, 행사 수정, 봇 삭제, 삭제 로그와 알림 형식을 검증합니다. 브라우저에서는 로그인·행사 등록 화면·행사 유형 입력을 검사합니다. 기본 브라우저는 Windows에 설치된 Chrome이며 다른 환경에서는 `BROWSER_EXECUTABLE` 환경변수에 Chromium 계열 브라우저 실행 파일 경로를 지정합니다.

외부 HTTPS 접속·운영 PC 자동 실행은 운영 설정을 연결한 뒤 확인해야 합니다. 실제 텔레그램 전송 검증 결과는 아래에 기록했습니다.

### 실제 텔레그램 알림 테스트

봇 토큰과 두 방 ID를 설정한 뒤 `node --env-file=.env scripts/check-telegram-live.js`로 실행합니다. **두 설정 방에 실제 테스트 메시지 9건을 보냅니다.** 운영 DB 대신 `artifacts/telegram-live/<실행시각>/runtime`에 별도 테스트 DB를 만들고, 방 연결·행사 신청·승인·수정·반려·취소 알림과 실제 참여 인원 입력 시 알림 미생성을 확인합니다. 검증 결과와 Telegram이 반환한 메시지 ID는 같은 실행 폴더의 `report.json`에 저장합니다. 자동 테스트에서는 이 스크립트를 실행하지 않습니다.

2026-09-15 실제 연동 검증에서 접수 알림방 6건, 업무소통방 3건 모두 Telegram API 전송 성공 응답을 확인했습니다. 외부 도메인 접속과 휴대폰 신청 화면은 아직 검증하지 않았습니다.
